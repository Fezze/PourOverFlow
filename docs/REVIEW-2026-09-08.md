# Project review — 2026-09-08

The review focused on phone/watch storage boundaries, history replay, snapshot scheduling, input validation, and session transitions under the existing `API_LEVEL 3.6` baseline.

## Findings and fixes

| Priority | Reproduction and impact | Fix |
| --- | --- | --- |
| High | Deliver a history entry, edit its note/rating on the phone, then replay the original watch entry after a lost acknowledgement. Replay overwrote the phone feedback and increased the revision again. | Watch delivery now acknowledges an existing `historyId` without rewriting the canonical record. Phone feedback editing retains its normal save path. |
| High | Edit a recipe and receive watch history during the 150 ms debounce. The immediate history flush cleared the pending catalog update. | Immediate flushes merge requested slices with already queued slices. |
| Medium | Persist JSON `null` in the watch catalog or sync metadata key and restart. Startup dereferenced null and threw. | Non-object top-level values fall back to the default catalog or sync metadata. |
| Medium | Deliver `UPSERT_HISTORY_ENTRY` with a null payload. The app-side listener threw before validation. | Missing entries now reach the existing validation rejection path. |
| Medium | Validate a recipe whose steps are an object or contain null. Duration summation threw instead of returning validation issues. | Duration validation runs only after checking the collection and its entries. |
| Medium | Pass a persisted completed, aborted, or expired session to resume. The reducer could reactivate it and rewrite elapsed time. Other transitions also accepted terminal sessions. | Terminal sessions remain unchanged through resume, advance, tick, and abort. |

Ten regression cases reproduce these failures against the original implementation. They exercise real project modules with the existing mocked Zepp runtime and phone transport harness.

## Simulator follow-up

A real simulator retry reproduced a black screen on Balance 2. The generated
page contained an unresolved `zosLoader:` import, and the simulator console
reported `API NOT EXIST zosLoader:./index.[pf].layout.js`. The previous successful
Zeus exit and browser previews had not caught this packaging fault.

The fix preserves all device targets and existing round/square layouts, adding
ordinary import facades that select the correct layout at runtime. Real-layout
module tests now cover every page on both screen shapes. The Zeus build wrapper
also rejects unresolved-import diagnostics even when Zeus exits zero.

A second tooling fix removes an unconditional `NaN` from the simulator doctor's
recursive timestamp calculation; fresh and stale deployment tests cover it.

Actual QEMU emulator captures confirm startup rendering on Balance 2 and Active
2 Square. The fresh square deployment passes the simulator smoke path. This is
startup evidence only: automatic touch injection did not reliably operate the
emulator, so a full brew, bootstrap, and history replay were not verified here.
The square emulator also exposed a native title bar covering the custom page
title. Every page now hides that bar before building its widgets; a fresh
Active 2 Square capture confirms the custom title is visible. Browser visual previews remain
separate from these emulator observations.

Final follow-up verification passed: 222 tests, Vitest coverage, all 130 visual
preview scenarios, Playwright module-harness smoke and coverage, and the full
Zeus build without unresolved imports. `sim:doctor` reports the Active 2 Square
deployment as fresh, and `sim:smoke` passes after deployment.

Local emulator captures are saved under
`output/playwright/watch-preview/simulator/` as `round-before.png`,
`round-after.png`, and `square-after.png`. These are actual QEMU window captures;
the separate `verify/` tree contains browser-mock screenshots.
